# Заметки ✨ — PWA-приложение (Практики 13–17)

Прогрессивное веб-приложение для управления заметками с офлайн-доступом, push-уведомлениями, напоминаниями и обновлением в реальном времени.

## Стек

- **Frontend:** HTML, CSS, JavaScript, Service Worker, Web App Manifest
- **Backend:** Node.js, Express, Socket.IO, web-push
- **PWA:** mkcert (HTTPS), App Shell архитектура

## Запуск

```bash
npm install
node server.js
```

Открыть в браузере: `http://localhost:3000`

---

## Практика 13 — Service Worker

Service Worker — это скрипт, который браузер запускает в фоновом режиме отдельно от веб-страницы. Он перехватывает сетевые запросы и позволяет кэшировать ресурсы для работы в офлайн-режиме.

В рамках данной практики реализован базовый менеджер заметок с офлайн-доступом:

- При первом посещении Service Worker устанавливается и кэширует все статические файлы (HTML, CSS, JS) в событии `install`
- В событии `activate` удаляются устаревшие кэши от предыдущих версий
- Событие `fetch` перехватывает все сетевые запросы: если ресурс есть в кэше — возвращается из кэша, иначе загружается из сети
- Заметки сохраняются в `localStorage`, поэтому доступны без интернета
- При отключении сети страница полностью загружается из кэша, добавление и просмотр заметок продолжают работать

## Практика 14 — Web App Manifest

Web App Manifest — это JSON-файл, который превращает обычный сайт в прогрессивное веб-приложение (PWA). Он позволяет устанавливать приложение на устройство и настраивать его внешний вид.

В рамках данной практики добавлен файл `manifest.json` со следующими полями:

- `name` и `short_name` — полное и краткое название приложения
- `start_url` — стартовая страница при запуске
- `display: standalone` — запуск в отдельном окне без интерфейса браузера
- `background_color` и `theme_color` — цвета фона и адресной строки
- `icons` — набор иконок разных размеров (16x16 до 512x512) для разных платформ

Также добавлены мета-теги в `index.html` для корректной интеграции с мобильными платформами: `mobile-web-app-capable` для Android и `apple-touch-icon` для iOS. Service Worker обновлён для кэширования иконок и файла манифеста. Приложение устанавливается на компьютер через кнопку в адресной строке Chrome и открывается в отдельном окне.

## Практика 15 — HTTPS + App Shell

HTTPS необходим для работы Service Worker и других PWA-возможностей. Для локальной разработки использована утилита `mkcert`, которая создаёт доверенный самоподписанный сертификат.

App Shell — это архитектурный подход, при котором минимальный каркас интерфейса (шапка, навигация, контейнер) кэшируется отдельно от динамического контента. Это даёт мгновенную загрузку интерфейса даже при медленном соединении.

Реализованные изменения:

- Проект переструктурирован: статический каркас в `index.html`, динамический контент вынесен в отдельные файлы `content/home.html` и `content/about.html`
- Навигация между страницами реализована через `fetch` — контент подгружается в контейнер без перезагрузки страницы
- Две стратегии кэширования в Service Worker: **Cache First** для статики (мгновенная загрузка из кэша) и **Network First** для динамических страниц `/content/*` (свежие данные из сети, при офлайне — из кэша)
- При полном отключении сети приложение загружается из кэша, страницы "Главная" и "О приложении" доступны офлайн

## Практика 16 — WebSocket + Push

WebSocket обеспечивает постоянное двустороннее соединение между клиентом и сервером, позволяя серверу отправлять данные без запроса со стороны клиента. Push-уведомления позволяют получать сообщения даже при закрытом приложении.

Реализовано с использованием библиотеки Socket.IO и Web Push API:

- При запуске приложения клиент подключается к серверу через Socket.IO
- При добавлении заметки отправляется событие `newTask` на сервер
- Сервер рассылает событие `taskAdded` всем подключённым клиентам — у них появляется всплывающий тост с текстом заметки
- Для push-уведомлений реализована подписка через `PushManager` с VAPID-ключами
- Добавлены кнопки включения и отключения уведомлений — подписка отправляется на эндпоинт `/subscribe`, удаляется через `/unsubscribe`
- Service Worker обрабатывает событие `push` и показывает системное уведомление операционной системы
- При перезапуске сервера подписка автоматически переотправляется при загрузке страницы

## Практика 17 — Детализация Push (напоминания)

Расширение функционала push-уведомлений: добавлена возможность создавать заметки с привязкой к конкретному времени, а также откладывать напоминание на 5 минут.

Реализованные изменения:

- В форму добавлено поле `datetime-local` для выбора даты и времени напоминания
- Структура данных заметок расширена: каждая заметка содержит уникальный `id` (timestamp), текст и поле `reminder` с временем напоминания
- Заметки с напоминанием отображают дату и время в списке
- При добавлении заметки с напоминанием клиент отправляет событие `newReminder` на сервер с `id`, текстом и временем
- Сервер планирует отправку push-уведомления через `setTimeout`, активные таймеры хранятся в `Map`
- В push-уведомлении для напоминаний передаётся `reminderId` — идентификатор для последующего откладывания
- Service Worker обрабатывает событие `notificationclick`: при нажатии кнопки "Отложить на 5 минут" отправляет POST-запрос на эндпоинт `/snooze`
- Эндпоинт `/snooze` отменяет текущий таймер и создаёт новый с задержкой 5 минут
